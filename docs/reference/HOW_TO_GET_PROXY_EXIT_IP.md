# 如何获取代理出口 IP（用于 OKX API 白名单）

## 背景：为什么需要这个 IP

OKX API Key 的 IP 白名单校验的是**代理节点的出口公网 IP**，而不是你电脑本机网卡的 IP。

- 你本机的 IP（例如 `192.168.x.x`）是**内网地址**，OKX 根本看不到。
- 本机所有对 `www.okx.com` 的请求都经过本地代理（Clash），OKX 只能看到代理节点最后出去的那台服务器的公网 IP。
- 代理如果开了「自动选择 / 负载均衡」，节点会漂移，出口 IP 就会变，白名单就失效。

所以关键前提是：**先把代理节点固定住，再查出口 IP**，否则查到的 IP 用不了几天。

---

## 第一步：确认代理端口

先找到本地代理的 HTTP 端口。常见的是 `7897`（Clash Verge / Vortex 的 mixed-port）。

```bash
# 查看谁在监听 7897 端口
lsof -nP -iTCP:7897 -sTCP:LISTEN
```

如果输出里有一个进程名（如 `com.vortex.helper` / `mihomo` / `clash`），说明代理就在这个端口。

---

## 第二步：固定代理节点（关键）

如果节点是「自动选择」，出口 IP 会一直变，白名单永远对不上。

### 方式 A：通过代理软件界面手动固定

打开你的代理软件（Clash Verge 等），在「代理」页把全局节点**手动选到一个固定节点**，不要用「自动选择」。

### 方式 B：通过外部控制器命令行切换（进阶）

Clash 内核通常有外部控制器（external-controller），可用 API 切换节点。

```bash
# 1) 找到外部控制器端口（进程启动参数里带 -ext-ctl）
ps aux | grep -iE "clash|mihomo|vortex" | grep -v grep

# 2) 查看当前 GLOBAL 节点选的是什么
curl -s http://127.0.0.1:39797/proxies/GLOBAL | python3 -c "import json,sys; print(json.load(sys.stdin)['now'])"

# 3) 切到一个固定节点（把「节点名」换成你要的）
curl -s -X PUT -H "Content-Type: application/json" \
  -d '{"name":"🇭🇰|香港-直连"}' \
  http://127.0.0.1:39797/proxies/GLOBAL -w "HTTP=%{http_code}\n"
```

> 注意：外部控制器端口（上面示例 `39797`）以你实际进程参数为准。

---

## 第三步：查询代理出口公网 IP（IPv4 与 IPv6）

一个代理节点可能同时有 IPv4 和 IPv6 两个出口，**OKX 实际走哪个不确定**，所以两个都要查、都要填进白名单。

### 3.1 查 IPv4 出口

```bash
curl -x http://127.0.0.1:7897 -4 https://api.ipify.org
```

命令解释：

- `-x http://127.0.0.1:7897`：强制走本地代理
- `https://api.ipify.org`：一个返回「请求来源公网 IP」的免费服务
- `-4`：强制走 IPv4

### 3.2 查 IPv6 出口

IPv6 用另一个服务 `api64.ipify.org`，并且**不要加 `-4`**，让请求自然解析到 IPv6 地址：

```bash
curl -x http://127.0.0.1:7897 https://api64.ipify.org
```

如果返回一个以冒号分隔的长地址（例如 `2a06:a005:87f:ffff::102`），那就是 IPv6 出口。

> 注意：`api.ipify.org` 默认可能只回 IPv4；要拿 IPv6 必须用 `api64.ipify.org`。

### 3.3 最可靠的方法：用 OKX 报错反推（推荐）

上面的方法查的是「代理对 ipify 的出口」，但不一定等于「代理对 OKX 的出口」（不同目标可能走不同节点/协议）。**最准的办法是直接看 OKX 报错**。

用 Key 调用任意私有接口（例如查余额、或直接下一单），如果 IP 不在白名单，OKX 返回的错误里**直接写着它看到的源 IP**：

```
{"code":"50110","msg":"Your IP 2a06:a005:87f:ffff::102 is not included
in your API key's 8148d3a0-... IP whitelist."}
```

`msg` 里的那个地址（上例 `2a06:a005:87f:ffff::102`）就是 OKX 真正看到的出口 IP，**以这个为准**，无需猜测。

如果报错里是 IPv4（形如 `45.67.201.102`），就填 IPv4；是 IPv6 就填 IPv6；两者都可能出现时，两条都填。

### 3.4 验证稳定性

无论查哪种，都要连续跑几次确认不变：

```bash
# 连续查 IPv4
for i in 1 2 3 4 5 6; do
  curl -s -x http://127.0.0.1:7897 -4 https://api.ipify.org
  echo
  sleep 2
done

# 连续查 IPv6
for i in 1 2 3 4 5 6; do
  curl -s -x http://127.0.0.1:7897 https://api64.ipify.org
  echo
  sleep 2
done
```

6 次结果完全一致，说明节点已固定，这些 IP 可以放心填进白名单。

---

## 第四步：把 IP 填到 OKX 白名单

1. 登录 OKX → 交易 → **模拟交易** → 个人中心 → **模拟盘 API**
2. 找到对应 Key → 编辑
3. IP 白名单填上第三步查到的地址，**IPv4 和 IPv6 都要填**：
   - IPv4 建议填网段，例如 `45.67.201.0/24`（覆盖网段内漂移）
   - IPv6 填完整地址，例如 `2a06:a005:87f:ffff::102`
4. 权限勾选「读取 + 交易」
5. 保存

---

## 常见问题

**Q：为什么要固定节点，不能直接清空白名单吗？**

模拟盘 Key 理论上可以不绑 IP，但 OKX 部分页面强制要求填 IP；而且不绑 IP 的 Key 安全性差。固定节点 + 绑 IP 是最稳的做法。

**Q：代理切节点后白名单失效怎么办？**

重跑第三步，拿到新 IP，再回 OKX 改白名单。

**Q：怎么验证 IP 是否已被 OKX 接受？**

用 Key 调用任意私有接口（如查余额），如果返回 `code=0` 说明 IP 通过；如果返回 `50110`，说明 IP 不在白名单。
